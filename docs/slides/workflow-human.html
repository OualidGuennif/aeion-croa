How work flows here

Agents plan, build, check and review their own work. You decide what matters: the plan, the decisions, the deploys. This is the whole flow on ten pages.

Workflow_human2
Step 1

Plan first, then a yes

For anything bigger than a typo, the agent reads the code and the docs it will touch, proposes the smallest change that fits, says what it will not do, and waits.

What you read

The context, the change, what is out of scope, and the checks that will prove it.

What you answer

Yes, no, or the one question that changes the plan.

What you skip

Reading every file yourself: the plan names them.

Workflow_human3
Step 2

Build in thin slices

1A branchOne task, one branch: task/<slug>.
2A small sliceThe smallest change that moves forward, its test first.
3Instant feedbackThe language server and the hooks speak after every edit.
4A green commitEach slice passes its tests and the pre-commit.

Secrets are never read. A broken link or a missing doc is caught in seconds, not in review.

Workflow_human4
Step 3

Sign off before the pull request

  • Testsfor what changed, with the command and the result
  • Docs and linksevery doc that describes the changed code is updated, or says why not
  • Task statethe open-task list is updated, or the task is removed when done
  • Securitya verified scan when the change touches auth, infrastructure or secrets
Workflow_human5
Step 4

A fresh reviewer, one comment

A new agent with a clean context reviews the diff. Every finding is verified before it is reported. The pull request gets one short comment:

Review: NOT OK
- high  src/billing/invoice.ts:42 -- rounding before the tax total
- low   README.md:12 -- the start command changed
Checks: CI green; doc-links pass; tests: 214 passed
Workflow_human6
Step 5

Merge when it is green and OK

Merges on its own

Review OK + green CI

Squash merge. The commit message carries the story, so docs stay short.

Waits for you

Decisions and deploys

Anything about money, risk, data deletion or policy waits before the merge. A deploy waits for your go.

Workflow_human10
The bigger picture

Seven phases, from quarks to a galaxy

1QuarksShort rules, policies, security, a tidy tree.
2AtomsNative language servers.
3MoleculesDocs bound to code, checked.
4CellsSkills for what repeats.
5OrganismsHooks: reflexes on every edit.
6ConstellationsInner, middle, outer loops.
7GalaxyMemory, decisions, self-improvement.

Each phase stands on its own. Apply them in order, one pull request per phase — and the repository gets a little cheaper and calmer every week.
